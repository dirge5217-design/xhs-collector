# 小红书零浏览器采集器

面向公开笔记数据的本地采集工具。运行期不启动浏览器，请求所需的签名由本地 Node 服务生成；采集结果写入本地 SQLite，并可导出为 CSV。

> **使用须知**：本项目仅用于技术学习与个人研究。使用前请确认并遵守目标站点的服务条款及所在地法律法规，仅处理公开可见数据，并保持合理的访问频率。使用者需自行承担使用本工具产生的责任。

---

## 1. 项目简介

「小红书零浏览器采集器」以 Python 采集器为核心，配合一个本地常驻的 Node 签名服务。登录凭据由使用者自行准备，之后的列表、详情与评论请求均通过标准 HTTP 完成，不依赖浏览器自动化框架，因此称为「零浏览器」。

工具覆盖四类数据来源：推荐流、关键词搜索、指定用户的笔记、以及指定的笔记 ID 列表。笔记与评论分别落库，支持按 ID 去重、断点续跑与请求限速；结果可按本次运行范围导出为 CSV。

设计要点：

| 要点 | 说明 |
|---|---|
| 本地签名 | 签名服务常驻运行，采集器按需调用，避免重复初始化开销 |
| 本地存储 | 单个 SQLite 文件保存笔记、评论及完成标记 |
| 可控节奏 | 默认请求间隔 1.5 秒，并带随机抖动 |
| 范围清晰 | CSV 默认只导出本次运行涉及的笔记，避免混入历史数据 |

---

## 2. 主要功能

| 功能 | 说明 |
|---|---|
| 四种采集模式 | `homefeed`（推荐流）、`search`（关键词搜索）、`user`（指定用户笔记）、`note`（指定 noteId 列表） |
| 笔记详情补全 | 补充正文全文、图片数、标签、互动数据等字段 |
| 评论采集 | 按页抓取一级评论，可选通过 `--sub-comments` 一并抓取楼中楼 |
| 去重与断点续跑 | 笔记按 `id` UPSERT、评论按 `id` 去重；`detail_done` / `comment_done` 标记避免重复抓取，中断不丢已落库数据 |
| 限速与重试 | 请求间隔可配置，失败自动重试并记录失败原因 |
| CSV 范围导出 | 默认按本次运行范围导出笔记与评论，`--csv-all` 可导出整库 |
| 自解释日志 | 每篇笔记固定一行，明确区分「总评」「入库评论」及差额来源 |

## 3. 环境要求

| 组件 | 要求 |
|---|---|
| Python | 3.10 及以上，需安装 `requests` |
| Node.js | 18 及以上 |
| 依赖安装 | `npm install` 与 `pip install requests` |
| 网络 | 可按需通过 `--proxy` 指定代理；无代理环境可用 `--proxy ""` 关闭 |

`node_modules` 不随仓库分发，获取代码后需自行执行 `npm install`。

## 4. 安装与配置

### 4.1 安装依赖

```bash
npm install
pip install requests
```

### 4.2 配置登录 Cookie

在项目目录创建 `_xhs_cookie.txt`，内容为使用者本人有效的完整 Cookie（单行），至少包含 `a1` 与 `web_session`；也可以通过环境变量 `XHS_COOKIE` 提供，采集器在找不到文件时会读取该变量。

`_xhs_cookie.txt` 属于账号凭据，已由 `.gitignore` 排除，请勿提交或外发。

### 4.3 目录结构

| 文件 | 作用 |
|---|---|
| `xhs_collect.py` | 采集器：四种模式、SQLite 落库去重、断点续跑、限速重试、CSV 导出 |
| `xhs_sign.js` | 本地签名实现 |
| `_eval_captured.js` | 签名服务运行所需的本地依赖文件 |
| `xhs_signer_server.js` | 常驻 HTTP 服务，提供签名与健康检查 |
| `package.json` | `jsdom` 依赖声明 |
| `.gitignore` / `.gitattributes` | 排除凭据、采集数据、依赖与缓存；保证文件换行一致 |

## 5. 快速开始

```bash
# 窗口 A：启动常驻签名服务，保持运行
node xhs_signer_server.js 18080

# 窗口 B：采集「咖啡」前 3 页，抓详情 + 每篇 2 页评论，导出 CSV
python xhs_collect.py --mode search --keyword 咖啡 --pages 3 \
    --detail --comments 2 --db xhs.db --csv 咖啡.csv --rate 1.5
```

签名服务提供 `/health` 健康检查。服务需保持常驻，以避免每次请求重新初始化签名依赖。

## 6. 命令参数

| 参数 | 说明 |
|---|---|
| `--mode` | 必填，`homefeed` / `search` / `user` / `note` |
| `--keyword TEXT` | `search` 模式的关键词 |
| `--user-id TEXT` | `user` 模式的用户 ID |
| `--notes FILE` | `note` 模式的列表文件，每行 `<noteId> [xsec_token]` |
| `--pages N` | 列表最多翻几页，默认 5 |
| `--detail` | 对每条笔记抓详情，补全正文、图片数、标签等 |
| `--comments N` | 抓评论，`N` 为每篇最多翻几页，`0` 表示不抓 |
| `--sub-comments` | 连楼中楼一起抓 |
| `--skip-done-comments` | 已抓过评论的笔记不再请求接口 |
| `--db FILE` | SQLite 文件，默认 `xhs.db` |
| `--csv FILE` | 额外导出 CSV，同时生成 `*_comments.csv` |
| `--csv-all` | 导出整库；默认只导出本次运行拿到的笔记 |
| `--rate SEC` | 请求间隔秒数，默认 1.5，带随机抖动 |
| `--proxy URL` | 请求代理地址；传 `""` 可关闭 |
| `--limit N` | 只处理前 N 条笔记 |

示例：

```bash
# 推荐流 5 页，仅建立索引
python xhs_collect.py --mode homefeed --pages 5

# 指定用户的笔记，并抓详情
python xhs_collect.py --mode user --user-id <用户ID> --pages 20 --detail

# 已有 noteId 列表，补齐详情和评论（含楼中楼）
python xhs_collect.py --mode note --notes ids.txt --comments 5 --sub-comments
```

## 7. 输出与数据说明

### 7.1 日志格式

每篇笔记固定打印一行，字段以 `|` 分隔：

```
[60/66] <noteId> | 详情 OK 赞17 总评7 | 入库评论 +3（一级3 · 楼中楼4 未抓） | 笔记标题
```

| 字段 | 含义 |
|---|---|
| `详情 OK 赞 N 总评 M` | 详情抓取成功；`总评` 是笔记展示的评论总数，含楼中楼回复 |
| `入库评论 +N（...）` | 本次去重后真正写库的新增行数，括号内说明差额来源 |
| 末尾标题 | 详情标题，或正文前 30 字 |

括号内片段：

| 片段 | 含义 |
|---|---|
| `一级X` | 本次返回的一级评论条数（去重前） |
| `楼中楼Y` | 启用 `--sub-comments` 时实际抓到的回复条数 |
| `楼中楼Y 未抓` | 未启用 `--sub-comments` 时，按回复数累加出的待抓条数（估算） |
| `无楼中楼` | 一级评论下没有回复 |
| `去重Z` | 接口返回但库内已存在、被忽略的条数 |

`总评` 与 `+N` 不相等属于正常情况：最常见原因是未展开楼中楼，其次是 `--comments` 只翻了部分页、部分评论不可见，或本次抓到的评论在库中已存在。`+N` 始终是新增行数，而非库内总数。

`入库评论 0` 会区分三种情况：

| 日志 | 含义 |
|---|---|
| `入库评论 0（库内已有 N 条，全为重复）` | 此前已抓取，数据未丢失，只是没有新增 |
| `入库评论 0（接口未返回评论）` | 请求成功但评论列表为空 |
| `评论 已抓过(跳过，库内 N 条)` | 启用了 `--skip-done-comments`，未发起请求 |

每 20 条打印一次进度行；结束汇总给出「评论新入库（去重后）」总增量与「本次接口返回：一级 N 条 / 楼中楼 N 条」，后者用于核对差额；「库内合计」为整库累计。失败会明确打印 `详情 失败(...)` / `评论 失败(...)`，且不会被标记为已完成，下次运行会重试。

### 7.2 去重与断点续跑

同一 `xhs.db` 重跑即可续跑。笔记按 `id` UPSERT，评论按 `id` 去重，`detail_done` / `comment_done` 两个标记避免重复抓取；按 `Ctrl+C` 中断不会丢失已落库数据。默认数据库由多个关键词共用，靠 `keyword` 列区分，因此同一篇笔记命中多个关键词时，后续运行会显示「全为重复」。

### 7.3 CSV 导出范围

默认只导出本次运行拿到的笔记（`--mode search` 时按关键词过滤），评论按同一批 noteId 过滤，不会串入其它话题。需要导出整个库时使用 `--csv-all`。若希望每个话题的物理文件完全独立，可为每次任务指定不同的 `--db`，例如 `--db 上海博物馆.db`。

### 7.4 输出字段

笔记表包含 id、作者、标题、正文、赞藏评享、图片数、标签、IP 属地、发布时间、带 token 的原文链接、`xsec_token`、来源与关键词；评论表包含评论 ID、所属笔记、父评论、昵称、内容、点赞、时间与是否二级。`1.2万` 这类展示值统一转换为整数。

## 8. 必要说明

### 8.1 凭据与数据安全

- `_xhs_cookie.txt` 等价于账号凭据，请勿提交到版本库、外发或打包分发；也可改用环境变量 `XHS_COOKIE`。
- 采集结果可能包含公开的用户昵称、评论内容与 IP 属地，请妥善保管，避免随代码或日志外泄。
- `.gitignore` 已排除 Cookie 文件、SQLite 数据库与 CSV 导出文件，请勿强制加入版本库。
- 建议保持默认请求间隔（`--rate 1.5`）或更长，避免对目标站点造成压力。

### 8.2 使用边界

- 本项目不附带任何账号或登录凭据，登录凭据需由使用者自行准备，并在失效后更新。
- 仅采集公开可见数据，不处理非公开内容或个人隐私字段；遵守目标站点服务条款与所在地法律法规，不用于商业用途或大规模抓取。
- 目标站点调整接口或签名依赖时，相关功能可能需要同步维护；可先检查 `/health` 与登录态定位问题环节。

### 8.3 免责声明

本项目按现状提供，不对其输出数据的完整性、准确性或适用性作任何保证。使用者应自行评估使用行为的合法合规性与相应后果。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 提示签名服务未启动 | 启动常驻服务，并确认 `/health` 可访问 |
| 登录态校验失败 | 检查 Cookie 是否有效，以及网络与代理配置 |
| 请求读超时 | 检查网络连接，或通过 `--proxy` 指定可用代理 |
| 笔记打不开 / 返回空 | `xsec_token` 由列表接口下发且会过期，重新运行列表接口获取新令牌 |
| `url` 列带 `?xsec_token=...` | 属正常现象，该参数是打开笔记详情所需的短期访问令牌 |
| CSV 中混入其它关键词数据 | 默认已按本次运行范围过滤；如需整库导出请使用 `--csv-all` |
